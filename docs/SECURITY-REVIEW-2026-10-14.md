# 도플겡어_chat_gpt 브랜치 보안 점검

## 점검 범위

2026-10-14 기준 Android 대화 수집·저장·화면, 로컬 모델 파일, 웹 프로토타입 대화 기록, Git 저장소 유입 방지를 확인했다. 이번 검토는 소스 중심의 제한된 점검이며 침투 테스트나 완전한 보안 보증이 아니다. 실제 대화 원문은 출력하지 않았다.

## 변경 1: Android 데이터 보호

### 무엇을 변경했는가

- 암호화 파일별 잠금을 프로세스 안에서 공유해, 알림 수집·화면·정리 작업의 서로 다른 저장소 인스턴스가 동시에 덮어쓰지 않도록 했다.
- 추가·삭제·보존 기간 정리는 AtomicFile로 기록하고 실패하면 이전 파일을 복구한다.
- 손상된 암호문 또는 키 분실 시 조용히 데이터를 제거하지 않고 읽기/쓰기를 중단한다. UI는 일반적인 오류만 표시하고 원본을 유지한다.
- 복호화 과정에서는 키를 새로 생성하지 않는다. 메시지 ID 중복 방지도 저장소 잠금 안에서 수행한다.
- 검토·말투 입력·로컬 생성 화면에 FLAG_SECURE를 적용하고 자동 완성·키보드 개인화 학습 제한을 요청한다.
- 모델 파일은 코드에 고정한 파일 크기와 SHA-256으로 검사한 뒤 네이티브 엔진에 전달한다. 가져오기 실패 시 기존 모델을 유지한다.
- 평문 네트워크 전송을 명시적으로 금지하고, 비밀 키 파일·환경 파일을 Git 제외 대상으로 추가한다.

### 왜 변경했는가

기존 잠금은 인스턴스별이어서 동시에 처리되는 정리/추가 작업 사이에 데이터 유실 가능성이 있었다. 기존 복호화는 오류 레코드를 생략한 뒤 파일을 재작성해 손상 또는 키 분실을 데이터 삭제로 바꿀 수 있었다. 모델 헤더만으로는 승인한 모델인지 검증할 수 없었다. 화면 캡처와 최근 앱 미리보기에는 암호화 이전의 본문이 표시될 수 있었다.

### 호환성·동작 변화

기존 앱 ID, Keystore 별칭, 파일명과 암호문 레코드 포맷은 유지한다. 지원 모델은 현재 고정된 Gemma E2B GPU 파일 한 개이며 다른 모델은 기본 헤더가 맞아도 거부한다. 모델 변경 때는 코드의 신뢰 정보와 테스트를 함께 갱신해야 한다. 모델 로딩 전 전체 파일 검사가 추가돼 과거 측정값보다 로딩 시간이 늘 수 있다. 손상된 저장소는 원본 보호를 위해 새 메시지 저장이 중단될 수 있고, 복구 UI는 후속 과제다.

## 변경 2: 웹 기록 삭제·로그

- 전체 삭제는 v1·v2 기록 키를 함께 제거한다. 이전 버전 데이터로 삭제된 대화가 다시 생성되는 경로를 차단한다.
- 이전 성공 후 v1 원본을 제거한다. 이전 실패 시 원본은 유지한다.
- 저장·분석·클립보드 처리에서 예외 객체를 console.error로 출력하지 않는다. 예외 문자열에 원문 일부가 포함될 수 있기 때문이다.
- 웹 안내에 암호화 미적용 LocalStorage임을 명시한다. Android 암호화 기능이 웹에도 적용됐다고 오인하지 않도록 했다.

## 검증

- 웹 회귀 테스트 3개 통과: 삭제 후 복원 방지, 이전 후 원본 정리, 손상 입력 오류 로그의 내용 비노출.
- 웹 production 빌드 통과. 운영 의존성뿐 아니라 개발 의존성까지 검사해 source-map-js의 high 취약점(GHSA-68fv-2mgg-jv7q)을 확인하고 1.2.1에서 1.2.2로 갱신했다. 변경 후 전체 npm audit 결과 알려진 취약점 0개(검사 당시).
- Android assembleDebug, assembleDebugAndroidTest, lintDebug 통과. 정적 검사는 오류 0개, 기존 경고는 남아 있다.
- Android 기기 테스트 7개 추가: 동시 저장/중복 방지, 손상 원본 유지, 키 분실 원본 유지, 백업 복구, 올바른 해시, 같은 크기의 변조 파일 거부, 임의 파일/취소 거부.
- Android JVM 테스트 실행기에서 테스트 클래스 로딩 오류가 있어, Android Keystore 테스트와 함께 실기기 instrumentation 테스트로 구성했다. CI는 테스트 APK 컴파일까지 검증하고 실제 실행은 연결 기기에서 수행한다.
- 실기기 실행 결과: USB 디버깅 재승인 대기. 실행 완료 후 이 항목을 갱신한다.
- 주요 비밀 키 패턴 검색에서 일치 파일은 발견되지 않았다. 모든 비밀정보 부재를 보장하는 검사는 아니다.

의존성 권고: https://github.com/advisories/GHSA-68fv-2mgg-jv7q

## 남은 범위

- 웹은 평문 LocalStorage를 사용하는 프로토타입이며 암호화 제품으로 취급하면 안 된다. 브라우저 기록 삭제는 OS·디스크의 물리적 완전 삭제를 의미하지 않는다.
- FLAG_SECURE·키보드 학습 제한은 OS/입력기의 지원을 사용하며 악성 키보드·루팅 기기·외부 촬영까지 방어하지 않는다.
- debug APK의 run-as 접근은 개발용이다. 외부 배포는 release 서명·디버그 비활성화·모델 배포 정책을 별도로 점검한다.
- 기기 잠금과 별개인 앱 잠금, 손상 데이터 복구, 승인/말투 데이터의 개별 삭제 UI, 장시간 추론 검증은 후속 과제다.
