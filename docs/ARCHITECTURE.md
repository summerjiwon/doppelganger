# Doppelganger 아키텍처

## 데이터 흐름

```text
카카오톡 알림 이벤트
  → NotificationListenerService
  → 민감 정보 마스킹 · 중복 제거
  → 암호화 임시 보관함 (최대 24시간)
  → 사용자의 검토·승인
  → 암호화된 분석 후보 / 별도 말투 문장 저장소
  → [다음 단계] 로컬 말투 프로필 · 온디바이스 번역
  → [나중] 사용자가 누른 경우에만 AI 답장 추천
```

## 현재 저장소

| 저장소 | 들어오는 경로 | 보존 | 목적 |
| --- | --- | --- | --- |
| 임시 대화 | 허용된 카카오톡 알림 | 최대 200개·24시간 | 사용자가 검토할 후보 |
| 승인 대화 | 검토 화면에서 직접 선택 | 최대 1,000개 | 향후 관계 맥락 분석 후보 |
| 내 말투 문장 | 사용자가 직접 입력 | 최대 2,000개 | 개인 말투 프로필 후보 |

세 저장소는 각각 Android Keystore 키로 AES-GCM 암호화됩니다. 앱은 대화 내용을 로그로 남기거나 현재 서버로 전송하지 않습니다.

## AI 전략

### 로컬에서 항상 가능한 작업

- 문장 길이·문장부호·이모지·존댓말·종결어미 같은 말투 통계
- 언어 감지와 필요한 언어 팩만 설치하는 온디바이스 번역
- 정형화된 답장 형식 및 사용자가 설정한 관계·톤 선택

### 선택적 로컬 생성 AI

지원 기기에서는 Gemini Nano 같은 온디바이스 모델의 가용성을 확인해 짧은 재작성에 사용할 수 있습니다. 로컬 모델은 **사용자가 추천을 요청할 때만** 메모리에 올리고, 작업 후 해제합니다. 기기마다 지원 여부·응답 품질이 달라 필수 경로로 만들지 않습니다.

### 선택적 클라우드 AI

상대 감정·관계 맥락을 고려한 여러 답장처럼 고난도 생성은 사용자 탭으로만 실행합니다. 전송 대상은 사용자가 승인한 최신 맥락과 압축된 말투 프로필로 제한하고, 자동 호출·자동 전송은 하지 않습니다. API 키는 절대 APK에 넣지 않고 서버 또는 Firebase 같은 보호된 중계 계층에 둡니다.

## 배터리·메모리 원칙

- 알림 도착 이벤트로만 실행하고 반복 폴링하지 않는다.
- 유휴 상태에서 LLM을 실행하지 않는다.
- 번역 모델은 필요한 언어만 Wi-Fi에서 다운로드하고 장기간 미사용 모델은 삭제한다.
- 정리는 WorkManager와 `BatteryNotLow` 제약으로 예약한다.
- 대화 원문이 아닌 작은 말투 프로필과 요약을 우선 사용한다.
