# 브랜치 작업 및 한국어 기록 규칙

## 현재 브랜치

- 개발 브랜치: `도플겡어_chat_gpt`
- 시작 기준: `codex/local-reply-mvp`의 `f265e76`
- 선행 로컬 AI PR이 열려 있으므로 보안 PR의 비교 기준은 `codex/local-reply-mvp`로 지정한다. 선행 PR 병합 후 필요하면 main 기준으로 변경한다.

## 기능 단위의 기록

1. 작업 전 현재 브랜치·미커밋 변경을 확인한다.
2. fetch로 원격 상태를 확인하고 pull은 `--ff-only`로 수행한다. 강제 push는 하지 않는다.
3. 데이터 보호, 웹 수정, 문서/CI처럼 목적이 다른 변경은 한국어 커밋으로 분리한다.
4. 기능에 맞는 검증을 수행한 뒤 현재 개발 브랜치를 push한다.
5. PR 제목과 본문은 한국어로 작성하고, 무엇을 바꿨는지·왜 필요한지·검증 결과·미검증 범위를 기록한다.

## PR 본문 형식

```text
변경 내용
- 사용자에게 달라지는 동작과 관련 구성 요소

변경 이유
- 확인된 문제와 변경이 그 문제를 해결하는 방식

검증
- 실제 실행한 명령과 성공/실패 결과
- 미실행 항목과 이유

영향과 후속 과제
- 데이터 호환성, 동작 변화, 남은 제한
```

개인 대화·API 키·로컬 설정·대용량 모델은 커밋하지 않는다. 이전에 만든 제출용 PDF 등 요청과 무관한 미커밋 파일은 자동으로 포함하지 않는다. 검토용 PR 생성과 push는 수행하되, 병합은 별도 요청이 있을 때 진행한다.
