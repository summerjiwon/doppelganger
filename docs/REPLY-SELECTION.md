# 1단계: 관계·답변 의도 선택

## 구현한 흐름

`로컬 AI 답변 테스트` → 모델 불러오기 → 관계 선택 → 의도 선택 → 받은 메시지 입력 → 답변 생성.

- 관계: 업무, 친구, 연인, 가족, 기타
- 의도: 수락, 거절, 공감, 질문, 직접 입력
- 직접 입력 의도는 추가 설명을 필수로 입력한다(최대 300자).
- 받은 메시지는 최대 1,000자이며, 관계와 의도를 자동으로 확정하지 않는다.
- 생성 동안 입력을 잠그고 선택 상태를 불변 요청으로 복사한다. 결과 아래 실제 적용한 관계·의도를 표시한다.
- 관계·의도 변경 시 이전 초안을 지워 다른 설정의 결과로 오인하지 않도록 한다.

## 변경 이유와 범위

기존에는 입력 문장을 그대로 모델에 전달해 관계·대응 방향을 명확히 지정할 수 없었다. 관계·의도별 지침을 시스템 입력에 넣고, 상대 메시지와 직접 입력 의도는 JSON 데이터로 별도 전달한다. 입력 분리는 모델이 지침을 반드시 준수한다는 보장은 아니다.

현재는 관계별 기본 표현 규칙이다. 사용자 예문, 말투 통계, 대화방 식별·기억, 수정 기록은 아직 연결하지 않았다. 입력과 결과는 저장하거나 서버로 전송하지 않는다.

## 관찰된 생성 문제와 보완

가상 메시지 `이번 주 토요일 저녁에 만나서 밥 먹을래?`를 거절하도록 했을 때 모델이 `선약이 있어서`라는 주어지지 않은 사유를 생성했다. 거절 결과에서 선약·바쁨 등의 알려진 사유 표현을 감지하면, 사유 없는 관계별 기본 거절문을 표시하고 교체 사실을 안내한다.

이 검사는 알려진 표현에 대한 제한적인 보완이다. 모든 허위 사실·감정·약속을 검출하는 일반적인 사실 검증 기능이 아니므로, 사용자가 최종 문장을 확인해야 한다. 자동 전송은 하지 않는다.

## 검증 결과 (2026-10-14)

- `assembleDebug`, `lintDebug` 통과.
- SM-S938N / Android 16에서 `connectedDebugAndroidTest` 14개 모두 통과(실패·생략 0개).
- 새 검증 7개: 관계·의도 25개 조합의 입력 구분, 메시지/시스템 분리, 직접 의도 필수 입력, 길이 제한, 거짓 거절 사유 보완, 선택 UI와 보안 플래그, 실제 모델 생성 연동.
- 가상 메시지 하나를 업무·거절과 친구·거절로 각각 설정해 화면에서 실제 모델을 불러와 생성했다. 결과가 비어 있지 않고 알려진 `선약` 표현이 최종 초안에 남지 않음을 확인했다.
- 실기기 생성 테스트는 별도 설치한 모델이 있어야 한다. 모델이 없는 환경에서는 해당 테스트를 생략한다. GitHub CI는 앱/테스트 APK 빌드와 정적 검사를 수행한다.
- 자동 검증은 연결 동작을 확인한다. 관계별 자연스러움·나다움에 대한 40개 사례 품질 평가는 다음 작업이다.
